# 首次发布审阅清单

本版本为源码公开审阅版，尚未创建 tag 或正式 Release，也未修改运行中的 HA。源码上传或合入默认分支不等于 HACS 正式发行。`hacs.json` 是发布准备文件；实际远端检查结果以 GitHub Actions 为准。

## 审阅项目

- 确认项目显示名 Panasonic Bridge CN / 松下智家桥接，目标仓库 `Raaan/panasonic-bridge-cn`。
- 确认 @Raaan 作为维护账号，是否启用私人漏洞报告。
- 复核 MIT 与 Apache-2.0 来源链，补足历史继承文件的版权及 NOTICE，保留所有既有归属。
- 审查候选控制默认暴露是否适合首次公开发行；必要时另做实验功能开关。
- 检查三类设备矩阵，避免将其他型号、单方向反馈或离线测试称为完整实机支持。
- 在隔离 HA 环境安装本包，验证配置流、重新配置、重启、旧条目升级与实体 UID；本轮不向生产环境安装审阅版。
- 上传前人工复核全部文件；执行离线测试、敏感模式扫描和 HACS/hassfest 校验。

## 正式 HACS 发布步骤

本轮保留部署基线版本 0.5.0。首次正式发行时选定新的语义化版本，并同步 manifest、Changelog、版本徽章（如采用）、测试检查中的版本约束。

最终代码合入默认分支后，在同一提交建立 `v<version>` 标签和非 draft、非 prerelease 的 GitHub Release。发布后核对 tag、目标提交、远端 manifest 版本和 Release 状态，再验证 HACS 安装/升级。仅推送默认分支不能宣称 HACS 更新完成。

源码审查通过后可按维护者指示合入默认分支。正式发版、向上游提 Issue、请求推荐或联系贡献者是后续独立步骤，不因源码合并而自动执行。
