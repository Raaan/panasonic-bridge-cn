# 正式发行前的检查

目前已有家中运行的部署版本和公开源码，尚未创建正式 GitHub Release。后续发行前，需要完成以下检查。

## 代码和资料

- 确认型号说明、当前实现和实际测试结果一致。
- 检查新增代码的来源、许可和署名，补充仍缺少的历史资料。
- 确认配置、卸载、升级与旧实体兼容性，并完成 HACS/hassfest 检查。
- 检查公开文件，排除账号、会话、设备标识及个人配置。
- 确认问题反馈入口和安全报告方式可用。

## 版本与发布

选定正式版本后，同步 manifest、Changelog 及使用的版本徽章。在最终默认分支提交上创建 `v<version>` 标签，再建立非 draft、非 prerelease 的 GitHub Release。

发布后核对远端 manifest、tag、提交和 Release 状态，再检查 HACS 安装及升级。只上传源码或合并分支还不算完成 HACS 发版。

源码合并、正式发行、目录收录和向上游提交改动分别处理。发布新版本时，保留清楚的升级说明和已知问题。
