# 脱敏调试案例

以下是依据开发记录重写的结构化案例，不是原始日志、抓包或云端响应。保留帮助复现的型号、端点、字段、错误类型和验证边界；删除账号、密码、会话、token、MAC、deviceId、家庭名称、房间、地址、实体 UID 和个人操作时间线。示例省略所有身份字段，不能直接用来调用云端。

## 1. 净化器发现失败：类别不匹配

**现象**：F-75C5PJD 已登录且可列出设备，但沿用社区 `0830` 类别过滤后未匹配。

**定位**：只读核对绑定设备的类别和子类型。本型号实际类别为 `0810`，子类型 `75C5PJD`；这不代表 `0830` 设备可以套同一协议。

**修复**：设备过滤采用 `0810`、子类型前缀和云端型号 `F-75C5PJD` 的组合。

**离线断言**：合成 `0810/75C5PJD/F-75C5PJD` 可发现；相同型号但类别 `0830` 不被误认。首次发现测试只需要合成数据，不需要公开真实 deviceId。

## 2. 空调状态查询失败：请求封装错误

**现象**：通用探测工具按净化器格式把身份参数嵌套进 `params`，空调 GET 不成功。

**定位**：`ACDevGetStatusInfoAW` 使用顶层身份字段及 `xtoken: SSID=<SESSION>`。该会话值必须由运行环境注入，不能写入文档、测试日志或 Issue。

**修复**：空调 GET 单独构造顶层请求，保留正确会话头；不能据错误封装的失败推断该端点不支持型号。

**边界**：GET 成功只证明读取路径，不证明 SET。观测到 `runStatus=49`、`runMode=66` 等新协议编码时，不套旧控制器的 0/1 电源值或温度乘二规则。室温原始 128 不解释成真实温度。

## 3. 净化器缺少四模式：实时字段不完整

**现象**：NeedsAP 实时状态能够读取电源和风量，但无法区分完整四模式与独立等离子体。

**定位**：绑定设备列表的 `statusAll` 含扩展字段，有些数值是字符串。候选 `ADevGetStatusODM` 返回 HTTP 404；没有继续猜测 ODM SET。

**修复**：解析允许的数值字符串，将缓存 `runSta`、`airVo`、`nanoe` 与实时值交叉校验，再使用 `runM` 与 `uvSterilization`。不同步则不提供扩展控制状态。

**结果**：模式表为轻柔 0、自定义 1、消毒 2、智能托管 3。一次消毒切轻柔结果为 `runM: 2 -> 0`、`airVo: 5 -> 1`、NanoeX/等离子体 `1 -> 0`，有 App 与实体反馈。仅覆盖该方向，不推定全部模式或独立等离子体写入通过。

**限制**：缓存没有可靠设备更新时间；基础字段一致不能完全证明扩展字段新鲜。公开代码保留默认关闭的旧 GET 诊断，但普通使用无需触发。

## 4. 空调灯光未变化：端点和最小载荷

**现象**：旧 AW 单字段灯光写入没有确认效果。

**定位与修复**：保留值域和新鲜基线检查后，经 `ACDevSetStatusNewProtocol` 仅发送灯光目标字段。

```json
{"params": {"lamp": 0}}
```

此片段不包含身份或会话，不是完整请求。

**结果**：回读 `lamp: 1 -> 0`，实体灯亮得到确认；该型号的灯光含义反转，0 为亮、1 为灭。

**边界**：没有补测反方向，不自动重发。该最小载荷结论不能推广为所有空调功能都只发一个字段。

## 5. 冰箱受理后未确认：Fridge-19 官方格式

**现象**：节能导航操作在读回等待结束后未确认，App 仍显示原状态。

**定位**：其他冰箱系列的候选载荷不能直接等同于 Fridge-19。协议资料表明该族使用 24 个控制字段、`isTodoLimit=1` 与 SET 会话头。

**修复**：读取新状态，校验三个主温区，构造官方字段集；只接受一个用户目标。按协议处理快速制冰与制冰停止/新鲜冻结互斥，避免复制门状态、当前温度或身份字段。命令发送一次，约 12 秒后只读确认。

**结果**：节能导航开启和关闭均有 App 同步反馈，三个温区设定未变。快速制冰有成功反馈，但未区分双向。温度设定和其他功能没有完整验证。

**限制**：可选字段缺失时默认 0；适配其他机型前必须检查是否会改变非目标设置。不能把服务端任务号视为执行成功。

## 6. Python 升级后 TLS 失败：旧证书约束

**现象**：新版 Python/OpenSSL 严格校验出现 `invalid CA certificate`；较早环境曾使用相同证书成功连接。

**修复范围**：仅对内置历史信任证书的确切 DER 指纹恢复兼容 X509 标志，继续保留证书、主机名和有效期检查，并拒绝重定向。不设置 `CERT_NONE`，不改系统信任库。

**边界**：该证书来源尚未独立核验；指纹匹配不是独立身份核验。证书轮换应先核对来源，不能用关闭 TLS 检查作为修复。

## 7. 空调关机未确认：网络因素与证据不足

**现象**：关机指令读回未确认；候选单字段关机同样一度未确认。后来发现设备网络掉线，网络恢复后设备已关机。

**结论**：无法据此单独判定协议修复成功或失败。保留单字段关机与额外一次延迟读取，不重复 SET；需在网络稳定时另做有明确范围的手动验证。
