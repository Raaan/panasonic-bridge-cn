# 已知问题与适用范围

目前所列净化器、空调和冰箱已在我的家庭环境中稳定使用。下面记录的是仍需注意的技术限制，便于其他用户判断自己的环境是否适用。

## 设备与状态

- 目前的实机结果对应已列型号，相近型号或相同类别编号仍可能使用不同协议。
- 空调室温编码尚未确认，`current_temperature` 保持为空，原始值 128 不能用作室温。其他未确认单位的传感器继续按原始诊断值展示。
- 净化器部分模式状态来自 `statusAll` 缓存。它会与实时电源、风量和 NanoeX 校验，但云端没有可靠的设备更新时间；不同步时相关控件可能暂时不可用。
- 滤网复位、空调内部洁净等未实现功能不在当前支持范围内。

## 云端与会话

- 依赖松下中国区云端，网络中断或接口调整会影响使用。
- 手机 App 和 HA 可能互相使会话失效。当前没有自动续期，需重新加载或重新配置。
- 控制命令不会自动重发。云端受理后仍需读回，读回失败时应先核对设备实际状态。
- 多设备共用命令锁，等待确认时后续命令会排队。大量设备和长时间断网的表现还需要更多实际反馈。

## 参数与兼容性

- 冰箱请求会保留官方控制字段，缺失的可选字段按 0 处理；空调会带上白名单内的新鲜状态。新增型号需要确认这些处理是否适用。
- 部分读取端布尔判断仍使用 `value in (0, 1)`，对类型的约束可以继续统一。设备标识当前主要检查分段，增加外部输入入口时应加强格式检查。
- 更换账号后，旧设备可能留下不可用实体，目前没有完整的自动清理策略，也没有独立 reauth 步骤。
- 已测试的 HA 版本为 2026.10.4。其他 HA 版本、固件和机型需要逐步补充验证。

## 后续核对

历史证书来源和部分早期代码出处仍在继续整理，详见 [安全说明](../SECURITY.md) 和 [文件来源](PROVENANCE.md)。默认关闭的诊断代码中还保留一个曾返回 404 的 ODM GET，普通使用无需开启。

正式发行前还需完成 HACS/hassfest、独立安装与升级检查，并持续收集外部用户反馈。后续新增未确认型号或功能时，会单独考虑实验性入口；现有已验证设备的状态见 [统一记录](VERIFICATION_STATUS.json)。
