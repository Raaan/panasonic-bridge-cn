# 已知限制与待审事项

1. 依赖中国大陆云端和未承诺稳定的 App API，网络/会话失效会导致不可用。无自动续期或重登冷却实现；这些是上游其他版本特性，不能复制为本项目说明。
2. 已部署 HA 2026.10.4；较早 HA 与不同 Python 版本兼容性未做矩阵测试。基础离线测试不能覆盖 HA 全生命周期。
3. domain、部分模块说明仍有 read-only 历史命名，但本版本有真实 SET 能力。文档和代码审阅时以实际方法为准。当前候选控制默认存在，没有统一实验功能开关。
4. 设备列表 `statusAll` 与实时基础值一致仍不能证明扩展字段新鲜；缺设备侧更新时间。模式/等离子体可能因缓存不同步不可用。
5. 空调没有可靠室温；原始温湿度、未知值与滤网字段不能直接用于温控自动化。缺少通用的异常传感器值过滤。
6. 布尔状态判断部分使用 `value in (0, 1)`，在 Python 中会接受 bool；控制协议多数使用严格 int 检查。后续可统一读取侧类型约束。
7. `gen_token()` 和设备标识校验只检查分段，不完整校验 MAC；当前目标来自云端发现，新增外部入口时应强化格式限制。
8. 错误被压缩成安全摘要，隐私保护有利，但排障细节有限。不要以上传原始响应弥补。
9. 重新配置更换账号后，旧设备可能保留不可用实体；没有完整设备清理迁移策略。配置流没有独立 reauth 步骤。
10. 多设备共享一个命令锁，读回等待会排队；周期轮询可与指令新鲜读取并行。尚未验证大量设备或长时间网络故障表现。
11. 公开证书历史信任来源未独立核验；证书轮换、有效期、Python X509 行为可能阻断连接。无自动证书更新。
12. 可选诊断仍包含已返回 404 的 ODM 候选 GET。默认不启用，不建议普通用户触发；没有 ODM SET。未来可单独移除旧探测入口。
13. 冰箱其他字段缺失默认 0；空调白名单会携带新鲜基线字段。新增机型需检查不相关设置是否保持，不能把“一次目标变更”误述为“只有一个字段写入”。
14. 真实设备验证不完整；详见设备矩阵。没有 UI 截图验证、HACS/hassfest 验证、长期稳定性测试或本轮逐项真实控制测试。
15. 直接上游 MIT 与早期上游 Apache-2.0 的逐文件来源尚未全部定位。两份许可及来源已保留；发布前继续核实继承代码中的版权/NOTICE，不宣称历史代码均为原创 MIT。

这些限制在审阅版中明确披露，不改变运行中的 HA。建议优先补设备验收矩阵、来源定位、候选控制开关，再扩大型号支持。
