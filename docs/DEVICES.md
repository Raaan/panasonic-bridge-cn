# 设备与协议

验证分三层：代码实现、历史只读/状态对照、历史真实控制结果。2026-11-11 本轮只核查源码和 HA，不重新控制设备。以下真实结果来自本地部署记录，不是本轮复测。

## 净化器

F-75C5PJD：类别 `0810`，不是上游待开发 Aircle 的 `0830`。发现要求型号精确匹配，子类型规范化后以 `75C5PJD` 开头。

- 状态端点 `ADevGetStatusNeedsAP`；控制端点 `ADevSetStatusNeedsAP`。
- 电源 `runSta` 为 0/1；历史用户确认过开机、关机实体结果。
- 四模式：轻柔 0、自定义 1、消毒 2、智能托管 3。完整缓存字段与实时电源、风量、NanoeX 对齐后才使用扩展状态。
- 历史消毒切轻柔：`runM` 2→0、`airVo` 5→1、NanoeX/等离子体 1→0，用户确认 App 和实体变化。此结果不覆盖全部模式方向。
- 风量选择轻柔会切模式；低/中/高为自定义模式下 2/3/4。跨模式可发送固定组合 `runM=1` 与目标风量，不隐式开机。急速 5 不作为普通自定义档开放。
- NanoeX、童锁、指示灯、显示屏按可用布尔状态提供控件；等离子体 `uvSterilization` 仅开机且自定义模式时可调。独立写入尚无完整验收矩阵。
- 不支持滤网复位。`fliterRemind` 保留协议原拼写。
- 基础状态包括 PM2.5、温湿度与滤网字段；除 PM2.5 等明确标注项外，原始诊断值未一律赋予物理单位。

## 空调

类别 `0900`，子类型规范化后以 `AIRCONCOMMON202401` 开头。CS-JM35K410Q 是现场使用型号；云端型号可能为空，代码退回显示协议名。不得据此声称所有 0900 空调或该协议族全型号已验证。

- GET `ACDevGetStatusInfoAW`；SET `ACDevSetStatusNewProtocol`。
- 电源运行 48、停止 49；制冷 66、制热 67、除湿 68；温度 16–30℃整数。
- 风速：自动 65、20% 49、40% 50、60% 52、80% 54、100% 55。
- 上下/左右风向有候选位置表；辅热仅制热开机时可调；NanoeX、睡眠要求开机；强智冷暖按当前模式开放；柔湿制冷要求专门支持标记。
- 灯光语义反转：`lamp=0` 表示灯亮，`lamp=1` 表示灯灭。历史单字段 `lamp=0` 有实体灯亮确认；反向未补测。
- 普通控制从新鲜 GET 白名单复制控制字段；灯光和关机使用单字段请求。不是所有操作都只下发一个字段。
- 关机曾出现读回不确认及网络掉线，后来恢复后关机。现有单字段修复不能标成完全通过或完全失败。
- `current_temperature` 固定 `None`。室内原始 128 不解码，亦无外部温度传感器回退。
- 无 auto、fan_only 模式；不承诺内部洁净、自清洁、定时、能耗或全部 App 功能。

## 冰箱

类别 `0100`，子类型规范化后严格为 `FRIDGE19`。现场型号 NR-E411BG-NH，但发现代码按协议族识别并显示 Fridge-19，没有型号硬限制。

- GET `FDevGetStatusInfo`；SET `FDevSetStatusInfo`，Cookie 及 SET 的 xtoken 会话头。
- 冷藏 `PCTempSet`：2–7℃；变温 `SCS1TempSet`：-3–4℃；冷冻 `FCTempSet`：-23–-17℃；步长 1。
- 六功能：速冻、快速制冰、制冰停止、新鲜冻结、节能导航、NanoeX。
- 官方格式为 24 个控制字段再加 `isTodoLimit=1`；仅接受一个显式目标变更。快速制冰会清除制冰停止及新鲜冻结；后两者开启会清除快速制冰。请求可改变互斥关联项。
- 缺失的其他官方字段默认 0；三个主温区必须有新鲜合法值。这一兼容策略仍可能影响其他协议族设备，不泛化承诺。
- 历史节能导航双向 App 同步通过，三区设定未变；快速制冰有成功反馈，未拆分方向；温控及其他功能缺完整逐项写入验证。

官方说明书参考：[NR-E411BG 说明书](https://home.panasonic.cn/support/attachments/auld/manual/NR-E411BG.pdf)。温控边界在旧部署记录中注明来自该说明书；本轮未重新审阅其内容，不将其作为新增实测证据。
