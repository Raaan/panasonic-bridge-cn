# 架构

## 运行路径

HA 配置流接收本地输入的凭据，使用执行器线程完成同步网络请求。`Client.login()` 顺序执行挑战令牌、登录、绑定设备发现。设备通过类别、子类型与部分型号过滤后，使用设备标识的 SHA-256 生成稳定 UID。

`PanasonicCoordinator` 每 60 秒读取状态，并将结果分发给 sensor、binary_sensor、switch、climate、select、number 六个平台。启动首次刷新不写设备；单设备失败显示不可用，全部设备失败触发更新失败。散列 UID 稳定但不应当作绝对匿名标识对外分享。

用户操作或 HA 服务调用进入实体方法，经协调器命令锁串行执行，调用客户端目标检查和协议参数构造，再交给传输层。锁覆盖控制及读回等待，不覆盖全部周期轮询。控制发送一次，延时只读刷新确认；空调关机额外允许一次延后读取，不再次 SET。

| 模块 | 责任 |
| --- | --- |
| `config_flow.py` | 登录、重复账号检查、重新配置；失败不覆盖旧凭据 |
| `__init__.py` | 生命周期、60 秒轮询、控制锁、读回确认 |
| `client.py` | 设备过滤、会话、数值白名单、设备类型约束、缓存交叉检查 |
| `transport.py` | HTTPS、固定云端域名、端点限制、15 秒超时、禁止重定向和系统代理 |
| `protocols.py` | 新协议空调枚举、边界与新鲜基线参数 |
| `purifier_protocol.py` | 四模式和 27 字段 skip=255 模板、完整状态检查 |
| `fridge_protocol.py` | 官方 24 字段格式、三区范围及功能互斥 |
| `entity.py` 与各实体平台 | 稳定标识、可用性、手动控制入口 |
| `calibration.py` | 默认关闭的诊断，限制字段、类型与公开枚举 |

## 登录与传输

登录使用上游兼容的挑战及 MD5 派生协议；设备 token 使用两层 SHA-512，保留标识后缀原大小写。这些是云端既有协议，不代表现代密码存储方案。账号密码保存在 HA 配置中，会话保存在运行内存。

固定服务地址为 `https://app.psmartcloud.com/App/`。通用 `post()` 仅允许认证、发现和 GET；独立方法支持受约束 SET。GET/SET 名称均通过 HTTP POST 调用。常规状态端点、空调顶层身份字段及冰箱载荷结构不同，不能直接互换。

## 本仓库边界

仅收录松下自定义整合及离线测试。美的、LG、小天鹅由其他成熟集成接入，不构成本整合支持范围。家庭面板、夜间关机规则、设备服务脚本、微信桥接、虚拟机磁盘、HA 数据库、原始响应、反编译 APK/JS 及调试备份均不打包。

保留历史 domain 和界面名称，避免实体迁移风险。项目显示名暂用 Panasonic Bridge CN，后续改界面名应独立验证，不应顺带改变 domain。
