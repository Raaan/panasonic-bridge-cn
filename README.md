# Panasonic Bridge CN · 松下智家桥接

[中文](README.md) | [English](README.en.md)

这是一个用于 Home Assistant 的松下中国区家电整合，目前支持我实际使用并完成验证的净化器、空调和冰箱。

已部署使用的版本为 0.5.0。目前尚未发布正式 GitHub Release，HACS 发行检查仍在完善。

## 为什么做这个项目

我在搭建家里的 Home Assistant 环境时，希望把不同品牌的家电放到同一个平台里管理。美的等设备已有可用的整合，而我使用的中国大陆松下型号，在当时找到的项目中没有直接适用的方案。

现有项目已经解决了登录认证和部分设备通信问题，我在这些工作的基础上继续适配自己使用的型号，逐步补齐净化器、空调和冰箱的状态读取与控制。这些设备目前已在家中稳定运行，现有功能也经过了实际核对。

我把代码和调试过程整理出来，是希望有相同设备的人能够直接复用，少走一些重复排查的弯路。也欢迎其他用户参与，帮助修复问题、补充型号、完善文档。一个人能测试的设备和投入的时间有限，希望这个项目能够慢慢成为大家共同维护的适配资料。

目前验证的是表中型号。相同品牌、类别编号或相近型号可能使用不同协议，新增型号仍需要单独确认。具体识别条件、字段和限制见 [设备说明](docs/DEVICES.md)。

## 和现有松下项目的关系

我参考和复用了现有中国区松下项目的认证与通信经验，重点补充它们当时未明确覆盖的具体型号。mcdona1d 项目主要支持线控中央空调和浴霸，rudyll 项目侧重新风与中央空调；osk2 项目面向另一套 Panasonic Smart App 设备定义。

本项目的主要补充是 `0810/75C5PJD` 净化器、`AirconCommon-2024-01` 空调和 `Fridge-19` 冰箱。详细对比及核查版本见 [与现有项目的区别](docs/COMPARISON.md)。后续若出现可以直接复用的新适配，我也希望优先协作，减少重复维护。

## 安装与配置

我使用的环境是 Home Assistant 2026.10.4，其他版本暂未完整测试。

1. 备份现有 HA 配置和整合目录。
2. 将 `custom_components/panasonic_home_readonly` 复制到 HA 的 `/config/custom_components/` 下。
3. 重启 Home Assistant。
4. 在“设置 → 设备与服务 → 添加集成”中搜索“松下智家（本地验证）”。
5. 在 HA 页面输入松下账号和密码，登录后会自动发现支持的设备。

更换账号或密码时，在集成条目菜单中选择“重新配置”。新凭据通过登录和设备检查后才会保存，失败时保留原配置。

升级现有安装时，请保留目录名 `panasonic_home_readonly`。这是早期沿用的名称，保留它是为了维持已有实体和自动化的兼容性；现在的版本已经包含设备控制功能。

## 使用说明

- 整合通过松下中国区云端通信，每 60 秒读取一次状态。“本地验证”指实际测试情况，通信仍然需要联网。
- 启动和正常轮询只读取状态。手动操作实体，或调用这些实体的 HA 自动化，才会发送控制命令。
- 控制命令只发送一次，随后读取状态确认。没有确认时请先检查 App 和设备实际状态，避免重复操作。
- 手机 App 与 HA 可能互相挤掉登录会话。会话失效后，需要重新加载整合或重新配置。
- 账号密码由 HA 的配置条目保存，请妥善保管配置目录和备份。证书及连接方面的说明见 [安全与隐私](SECURITY.md)。

我也在家中使用独立的微信 AI 工具调用 HA 控制设备。这只是一个可选的使用方式，微信工具单独维护，不包含在本仓库中。

## 参与项目

欢迎提交问题、修改代码、补充设备测试或完善文档。如果你的设备型号不同，可以先提供型号、协议类别和脱敏后的状态信息，便于判断是否能够复用现有适配。

开发和提交改动前，请阅读 [贡献指南](CONTRIBUTING.md)。调试经验见 [排障记录](docs/DEBUGGING_CASES.md)，后续计划见 [维护计划](docs/ROADMAP.md)。

无需账号和网络即可运行基础检查：

```sh
python test_readonly.py
python -m unittest discover -s tests -v
python tools/privacy_scan.py
python tools/review_check.py
```

测试结果和运行环境见 [验证记录](docs/VALIDATION.md)。自动化测试用于检查代码行为，真实设备兼容性仍需要对应型号的用户参与验证。
